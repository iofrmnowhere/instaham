# INSTAHAM — Setup Guide (`flutter build apk`)

This guide gets a fresh clone to a working `flutter build apk`. It covers the parts that
are **not** in git: the ML model binaries and the native prebuilt libraries.

---

## 1. What you receive

| Source | Contents |
|---|---|
| Git repo | The Flutter app (`lib/`), Android project, the `instaham_ml_ffi` package source, all `.json` model metadata, generated Drift code (`*.g.dart`). |
| ML zip (shared separately) | The model **binaries** that are gitignored. See section 3. |

Everything else is fetched by a script (section 4) or generated by the build.

---

## 2. Install the toolchain

Install these once per machine.

| Tool | Version | Notes |
|---|---|---|
| Flutter SDK | stable channel (tested on **3.44.8**, Dart 3.9.x) | `pubspec.yaml` requires Dart `>=3.9.2 <4.0.0`. |
| JDK | **17** | Android Gradle config targets Java 17. |
| Android SDK | Platform 34 + latest platform-tools & cmdline-tools | Install via Android Studio or `sdkmanager`. |
| Android NDK | **28.2.13676358** | Exact pin in `android/app/build.gradle.kts` and the FFI package. A different NDK can break the native build. |
| CMake (Android SDK) | **3.22.1** | Pinned in `packages/instaham_ml_ffi/android/build.gradle.kts`. |
| Git Bash / WSL (Windows) or a POSIX shell | — | Needed to run `fetch_deps.sh`. Requires `curl`, `unzip`, `sha256sum`. |

Install the NDK and CMake with the SDK manager, for example:

```bash
sdkmanager --install "ndk;28.2.13676358" "cmake;3.22.1" "platforms;android-34" "platform-tools"
```

Then verify and accept licenses:

```bash
flutter doctor
flutter doctor --android-licenses
```

`flutter doctor` should show no blocking issues for the Android toolchain before you continue.

## 3. Drop in the ML model binaries

The following files are **gitignored** (`*.onnx`, `*.pt`, `*.tflite` in `.gitignore`) and
must be copied in from the ML zip. `pubspec.yaml` lists them under `flutter: assets:`, so
**the build fails with a "unable to find asset" error if any are missing**.

Place them at these exact paths (relative to the repo root):

```
assets/ml/view/model.onnx
assets/ml/health/model.onnx
assets/ml/segmentation/yolo.onnx
assets/ml/weight/xgboost.onnx
```

The `.json` files next to them (`classes.json`, `preprocessing.json`, `manifest.json`,
`feature_order.json`, `xgboost.meta.json`) are already in the repo — do not overwrite them
unless the ML zip explicitly ships newer versions.

> If your zip only contains the `ML/` folder (Python training/export code), that is the
> wrong tree. You need the exported `assets/ml/` artifacts.

Verify:

```bash
ls assets/ml/view/model.onnx assets/ml/health/model.onnx \
   assets/ml/segmentation/yolo.onnx assets/ml/weight/xgboost.onnx
```

## 4. Fetch the native prebuilts

`packages/instaham_ml_ffi/src/third_party/` is **entirely gitignored** (its `.gitignore`
is `*`). The native C++ runtime needs ONNX Runtime and opencv-mobile, which the fetch
script downloads from pinned URLs and checksums:

```bash
bash packages/instaham_ml_ffi/scripts/fetch_deps.sh
```

This downloads and unpacks into `src/third_party/`:

- **stb_image** (image decode/resize headers)
- **nlohmann/json** 3.11.3 (single header)
- **ONNX Runtime** 1.17.1 (`onnxruntime-android` AAR → `libonnxruntime.so` for
  `arm64-v8a`, `armeabi-v7a`, `x86_64`)
- **opencv-mobile** 4.13.0 (static libs + CMake config package)

It is safe to re-run; already-downloaded files with a matching checksum are skipped.

Verify:

```bash
ls packages/instaham_ml_ffi/src/third_party/onnxruntime/lib/android/arm64-v8a/libonnxruntime.so
ls packages/instaham_ml_ffi/src/third_party/opencv/sdk/native/jni
```

## 5. Build

```bash
flutter pub get
flutter build apk
```

Notes:

- **No `build_runner` step is needed** — the generated Drift files (`*.g.dart`) are
  committed. Only re-run `dart run build_runner build --delete-conflicting-outputs` if you
  change the Drift schema.
- **No signing setup is needed** — `android/app/build.gradle.kts` signs release builds with
  the debug key for now. `key.properties` / keystores are gitignored and not required for
  `flutter build apk`.
- First build is slow: Gradle downloads AGP 9.0.1 / Kotlin 2.3.20 and CMake compiles the
  native library for three ABIs.
- Output APK: `build/app/outputs/flutter-apk/app-release.apk`.

For a smaller test APK, split per ABI:

```bash
flutter build apk --split-per-abi
```

## 7. Common failures

| Symptom | Cause / fix |
|---|---|
| `Error: unable to find directory entry in pubspec.yaml: .../assets/ml/...model.onnx` | Model binary missing — see section 3. |
| CMake error: cannot find `onnxruntime` / `OpenCV` | `fetch_deps.sh` not run, or run from the wrong directory — run it from the repo root. |
| `NDK did not have a source.properties file` / NDK version mismatch | Wrong NDK installed — install exactly `28.2.13676358`. |
| `fetch_deps.sh: sha256sum: command not found` (Windows) | Run inside Git Bash or WSL, not PowerShell/CMD. |
| Gradle / AGP 9 "unknown property" errors | Old Gradle cache — `flutter clean`, then rebuild. |
| `A problem occurred configuring project ':instaham_ml_ffi'` | Usually a missing `third_party/` tree — re-run `fetch_deps.sh`. |
