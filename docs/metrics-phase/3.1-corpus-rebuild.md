# Metrics plan phase 3.1 — corpus rebuild against `INSTAHAM_APP_REQUIREMENTS_AFTER_TRAINING.md`

Status: **done, partially superseded**. Rebuilds phase 3's fixture corpus; supersedes its
"Corpus selection" and "Per-scenario sourcing" sections. Adds no tests — this is fixture data
only, same as phase 3.

> **Superseded in part by `docs/metrics-plan.md` finding 9.** The reference object is now
> mandatory for every weight capture, and the height-calibrated alternative is withdrawn.
> **Scenarios 4 and 10 are removed** — both exist only to exercise a capture with no usable
> reference, which the required flow cannot produce. Everything this document says about those
> two scenarios is historical. The corpus is **nine** fixtures, keeping their original ids
> (1, 2, 3, 5, 6, 7, 8, 9, 11) so the one-to-one mapping onto §14's functional bullets survives;
> the two gaps in the numbering are deliberate. The generator, the fixture directories and
> `test/fixtures/scenarios/README.md` still carry all eleven; **phase 4 task 0** deletes them
> before any envelope is recorded.

## Why

Round 14's audit against `INSTAHAM_APP_REQUIREMENTS_AFTER_TRAINING.md` §14 (the origin spec
for all 21 skipped tests, per `docs/handoff.md`) found phase 3's corpus could not prove three
of the eleven functional bullets:

1. **§14 bullet 5 (side-view health image)** — scenario 5 was a dorsal PIGRGB image flagged
   `image_is_placeholder`, not a genuine off-dorsal capture.
2. **§14 bullet 7 (multiple-pig image)** — scenario 7 was a synthetic composite of two
   single-pig PIGRGB photos pasted side by side, not a real two-pig frame.
3. **§14 bullet 3 (valid custom reference length)** — scenario 3's "custom" reference was a
   pixel count derived from PIGRGB's fixed acquisition geometry (100/304 cm/px), with no
   reference object actually visible in frame. A fabricated scale, not a marked one.

The user then added two new real photos to `.pig_pictures/` (a second meter-stick capture,
`75kg_pig_meter_stick.HEIC`, with its tape span measured at 1582 px for 100 cm) and pointed
at `health_pigs/` (5 existing real farm photos, not previously used by this plan) as the
corpus to rebuild from — asking explicitly whether the rebuild should stop using
`Instaham/PIGRGB-Weight/` for scenario fixtures entirely. It does.

## `observed_phase4` blocks are gone, not stale

Round 14 ran the *old* corpus through the native harness and recorded results into each
`meta.json`'s `observed_phase4` / `phase4_blocked` block (`docs/metrics-phase/
4-scenario-envelopes.md`). `write_meta()` in `generate_fixtures.py` writes a complete fresh
dict per scenario, so regenerating removed those blocks entirely rather than leaving them
stale-but-present — every `meta.json` in the rebuilt corpus now has no `observed_phase4` key
at all. Phase 4 must re-run every fixture through the phase 2 harness from scratch; there is
nothing here to confuse with current results. This is called out in the fixture README's
"Known gaps" section.

One finding from that stale data is still relevant as a hypothesis, not a result: all four
`.pig_pictures/` handheld captures previously failed the cutter stage
(`no_terminal_balls`, `jiduan_failed`, `mask_implausibly_small`). The likely cause is
segmentation mask quality on handheld/oblique framing, not a defect in the cutter itself —
the cutter is validated against a Python oracle on PIGRGB (`model_and_cutter/*/VALIDATION.md`,
`ML/parity/`), and its `decline()` path returning a named reason on degenerate input is
designed behavior, not a crash. This needs to be re-checked against the rebuilt corpus,
starting with the mask each image produces, before it's treated as a known limitation of the
shipped pipeline.

## Not closed by this rebuild

- **§14 bullet 3 is still not a fully distinct object.** Scenario 3's 50 cm "custom" length
  is a real sub-span of the same meter tape as scenario 1's 100 cm reference, not a visually
  distinct third object with an independently known length. It exercises the custom-length
  code path (an app-entered value that isn't one of the two presets) but not a genuinely
  different physical reference. Closing this fully needs one more photo.
- **§14 bullet 6 (lesion close-up) is still an approximation.** `health_pigs/owaKvudb.jpg`
  shows red hand-drawn marks and visible rib striation, the closest available image to a
  lesion, but it is not a confirmed lesion photo.
- Reference pixel endpoints remain unmarked for every fixture with a real reference object
  (01, 02, 03, 11 — 10 is removed by finding 9) — unchanged from phase 3, still blocking a
  Tier B numeric assertion. With the reference object now mandatory, this is the corpus's
  most load-bearing gap: every surviving weight fixture needs its endpoints marked before
  phase 4 can write a Tier B numeric assertion at all.
