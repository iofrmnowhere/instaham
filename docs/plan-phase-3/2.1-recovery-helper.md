# Subphase 2.1 — move the coordinate recovery into a function the tests can call

Status: done

Surfaced while closing out phase 2 (session 13). Phase 2 shipped native tests for coordinate
recovery and aspect preservation (`test_health_input.cpp` groups 1 and 2), but those tests
re-implement the recovery arithmetic inline and check it against itself. The code that actually
runs, `pipeline.cpp:512-523`, is never called by any test. A regression in `pipeline.cpp` (a
multiply instead of a divide, one axis using the wrong field, a dropped `lround`) would leave
all of phase 2's tests green. This subphase closes that gap and nothing else.

## Goal

Make the BASE_MASK-to-original recovery a named function in `health_input.{h,cpp}`, have
`pipeline.cpp` call it, and have test groups 1 and 2 call the same function, so the tests pin
the code that ships. The pipeline's output must stay bit-identical.

## Design/Approach

### The function

Add to `health_input.h`, next to `PigRegion`:

```cpp
// Fills `out` from a pig mask in BASE_MASK space, recovering the bbox into ORIGINAL image
// coordinates by dividing by `content_scale` (SegmentationOutput::content_scale). The mask
// bitmap is passed through at its own resolution; prepare_health_input() resamples it.
// Returns false, leaving `out` untouched, when content_scale is not finite and positive or
// `mask` is null.
bool pig_region_from_base_mask(int bbox_x, int bbox_y, int bbox_w, int bbox_h,
                               const uint8_t* mask, int mask_w, int mask_h,
                               float content_scale, PigRegion* out);
```

It takes plain values, not `const stages::PigMask&`. `test_health_input` and
`health_input_gate_cli` compile only `health_input.cpp` and `util/image_io.cpp`
(`src/test/CMakeLists.txt:131-150`). Including `stages/construction.h` would pull
`SegmentationOutput` into a unit that has no stage dependency today. `pipeline.cpp` unpacks
`pig_mask` at the call site, which is one line.

The body is the current `pipeline.cpp:513-521` moved verbatim: the same guard
(`content_scale > 0 && isfinite`), the same `std::lround(v / double(content_scale))` on each of
the four edges, the right and bottom edges computed from `bbox_x + bbox_w` and `bbox_y + bbox_h`,
and `has_mask = true`. Do not "improve" the rounding or clamp here. Clamping already happens in
`prepare_health_input()`, and any change to the arithmetic would move the parity numbers phase 2
recorded.

### The call site

`pipeline.cpp:512-523` becomes:

```cpp
if (have_mask &&
    pig_region_from_base_mask(pig_mask.bbox_x, pig_mask.bbox_y, pig_mask.bbox_w,
                              pig_mask.bbox_h, pig_mask.pixels.data(), pig_mask.width,
                              pig_mask.height, seg_output.content_scale, &region)) {
  health_opts.region = region.valid() ? &region : nullptr;
}
```

The long comment at `pipeline.cpp:502-511` moves to the declaration in `health_input.h`. A
one-line pointer stays at the call site. The `PigRegion` comment (`health_input.h:55-64`) that
says "pipeline.cpp divides it back" is reworded to name the function.

### The tests

Groups 1 and 2 in `test_health_input.cpp` are rewritten to call `pig_region_from_base_mask()`
instead of doing the division themselves. The expected values stay as they are: (40, 20)-(120, 100)
at 0.25 gives (160, 80)-(480, 400), and a 60x30 box at 0.4 gives 150x75. Those values were
worked out by hand, not from the code, so they still work as independent checks.

New cases in the same two groups, each one pinning a branch the current tests cannot reach:

- `content_scale` of 0, negative, NaN and +inf each return false and leave `out` as it was.
- A null `mask` returns false.
- `mask`, `mask_w` and `mask_h` come back unchanged (the bitmap is not resampled here).
- A non-origin box at a factor that does not divide evenly (e.g. 0.3) checks `lround`
  rounding on all four edges. This is the case a truncating cast would fail.

One end-to-end case is added as group 2b. A synthetic capture at original size has the pig
area painted a distinct colour. A mask at a quarter of that size covers the same area in
BASE_MASK space. `pig_region_from_base_mask()` then feeds `prepare_health_input()` under
`kSegmentationMasked`, and the crop must contain the painted colour and the mean fill, and
nothing from outside the painted area. This checks the recovered box and the resampled mask
against each other on the code that ships. It uses synthetic pixels and does not replace the
parity gate.

### Out of scope

- **Phase 2 weakness 2** (the parity gate never touches `content_scale`, and its mask is a
  synthetic ellipse). Group 2b covers the recovery-plus-resample path on synthetic pixels, but
  the gate CLI still receives a box already in original coordinates. Changing the gate to go
  through the new function is possible, but it changes the gate's input format and is a
  separate decision.
- **Phase 2 weakness 3** (the `HEALTH_INPUT_MAX_ABS_DIFF = 150` tolerance). Unrelated to this
  code path.
- `pipeline-docs`: this is an internal helper. No FFI signature, stage order, model or tensor
  shape changes, so the pipeline docs are not touched. `docs/spec.md` is not touched either.

## Rating: 8/10

**Pros.** Small and mechanical: one function moved, one call site, two test groups rewritten.
It turns phase 2's two weakest tests into real ones, and the mutation check proves that instead
of just claiming it. Pipeline output does not change, so phase 2's recorded parity numbers stay
valid and phase 3 is not disturbed. The plain-values signature keeps `health_input` free of
stage headers.

**Cons.** It closes only weakness 1. The gate still skips the `content_scale` path on real
captures, so "phase 2 passed" is still bounded by weakness 2. Group 2b adds some coverage but
uses synthetic pixels. Rebuilding and running ctest costs about 200 s, almost all of it in the
unrelated `test_scale_normalization`.

**Why not higher.** It leaves weakness 2 open by choice. **Why not lower.** The risk is close to
zero, and the change is directly measurable.
