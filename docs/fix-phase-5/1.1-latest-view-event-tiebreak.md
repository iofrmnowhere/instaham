# Phase 1.1 — `resolveViewGate` must break ties on `id`, not `createdAt`

Status: done (applied together with phase 1, not deferred — see Why applied immediately)

Parent: [`../fix-5.md`](../fix-5.md) (round 9). Surfaced while implementing
[`1-view-verdict-cache.md`](1-view-verdict-cache.md); not part of F66 itself.

## Symptom

While writing phase 1's unit tests, resolving the same scan against image A, then image B,
then image A again produced only 2 model calls where 3 were expected: the third resolve, which
should have missed the cache (the latest stored event now describes B, not A) and re-classified,
instead returned a stale cached verdict.

## Root cause

`resolveViewGate`'s query selects the most recent `view` `PipelineEvent` with
`..orderBy([(row) => OrderingTerm.desc(row.createdAt)])..limit(1)`. `createdAt` is
`dateTime().withDefault(currentDateAndTime)`, which resolves to whole-second precision in
sqlite. Two `view` events written for the same scan within one wall-clock second — exactly what
a fast retake (phase 1's own scenario) produces — tie on `createdAt`, and `ORDER BY ... DESC`
with no secondary sort gives no guarantee about which of two tied rows comes first. The
autoincrement `id` column is the only column guaranteed to reflect actual insertion order.

## Change made

`resolveViewGate`'s query now orders by `OrderingTerm.desc(row.id)` instead of
`row.createdAt`. One line, same query phase 1 was already editing.

## Why applied immediately rather than deferred

This project's convention is to write up an issue surfacing mid-phase as its own numbered
subphase and flag it, not fold a fix into the phase already in progress. That is why this file
exists as `1.1` rather than as a paragraph in phase 1's own writeup. It was applied in the same
change as phase 1, not queued, because it sits in the exact function phase 1 modifies and phase
1's own verification tests (the retake scenario) cannot pass without it — deferring it would
have left phase 1 unverifiable. It is recorded separately so the fix is visible and attributable
on its own terms, not because the code change itself was held back.

## Verification

Covered by phase 1's own test suite — specifically
`test/features/inference_pipeline/view_verdict_cache_test.dart`'s first case (image A → image B
→ image A again, asserting 3 model calls). No separate test was added; see phase 1's Result
section for the full run.
